## Remaining

Measured on `origin/main` at commit `8bd6632`.

- The sewing palette has no contrast test: the tokens live in `apps/web/src/styles.css` (`--paper`, `--ink`, `--thread`, `--scar`, `--panel`, `--line`, `--accent`) and the AA contrast is claimed in the CSS comments, but no unit test measures a pairing, and there is no `seam` or `alt thread` token.
- The diff and the combine still run on the main thread: there is no web worker and no `useCombinePlan.ts`, so the loading and error states exist but the analysis is not offloaded (SUT-N-03).
- The free-entry field applies the typed value as it is: `guessKind` of `combine-model.ts` infers the kind (a value starting with `=` is a formula, a comma is read as a decimal separator), but there is no per-kind validation and no inline error.
- The two-way mode for an unknown origin (SUT-F-24) was not implemented: the common origin is computed (`apps/web/src/store/ancestry.ts`, with its tests including the unrelated case) and the combine is refused with `error.no-common-origin`. The missing-origin-marker prompt (SUT-F-06) was not implemented either: the marker is written when a version is saved (`apps/web/src/store/finalize.ts`) and read by `@suture/canonical`, but its absence triggers no prompt.
- The report is downloaded as a plain-text file (`suture-report.txt`) rather than as Markdown, and the automatic changes of step 1 have no jump-to-cell link.
- No test walks the three steps with the keyboard only, and the combine screen has no vocabulary scan of its own messages (the compare and workbook screens do).
